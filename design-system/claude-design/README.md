- **AI が読むとき**: 下の「使い方の決まり」を先に読む。部品を使う前に、その部品の `components/<部品>/README.md` と `components/index.d.ts` を読む。色や大きさは `tokens.json`(CSS では `tokens.css` の変数)から取り、数値を書き写さない

# 使い方の決まり

NAsVI は、技大祭(長岡技術科学大学)の来場者が、会場の中で企画・場所・混雑を手早く知るためのアプリ。来場者はスマートフォンの縦持ち(390×844)で、歩きながら片手で使う。運営は PC で、場所と建物を登録する。

## 原則(上ほど優先する)

1. **一目で分かる。** 歩きながら、数秒で分かる形にする。1 画面の主な操作(`Button` の `primary`)は 1 つまで。距離は大きな数字(`distance`・`distance-lg`)で出す。
2. **行き止まりを作らない。** うまくいかないときも、次の手を出す。`Banner` と `EmptyState` には必ず `actions` を渡す。絞り込み中に 0 件なら、先頭の手は「絞り込みを解除して探す」。
3. **今か古いかを正直に出す。** 現在地・混雑・案内には、更新の時刻と精度を添える(「10 秒前に更新・精度 ±8 m」)。古いときは `stale` の色にし、`PositionMark` は `stale` にする。古い混雑は、新しい情報として見せない。
4. **色だけに頼らない。** 屋外の日なたでも、色の見え方が違っても伝わるようにする。混雑は濃淡と数字、感想はマーク、行き先は黄と形と縁、選んだチップはチェックの印も出す。

ぶつかったら上を取る。ただし「一目で分かる」のために、古い情報であることを隠さない。

## 言葉

画面に出す言葉は、概念設計・API と同じものにそろえる。

| 画面の言葉 | 使わない言い方 | 決まり |
|---|---|---|
| 場所 / 企画 | 店舗、スポット | 企画だけのときは「企画」、駐車場や設備を含むときは「場所」。検索窓は「企画・場所を検索」 |
| 建物 | 棟、ランドマーク | すべて「建物」(「この建物の企画」)。「〜棟」は建物の名前の中だけ(「図書館棟」) |
| 種類(飲食・展示・体験・ステージ) | カテゴリ、ジャンル | 運営が付ける |
| タグ(行きたい場所・お気に入り・自作のタグ) | ラベル、ブックマーク | 来場者が付ける。端末の中にだけ保存する |
| 絞り込み、絞り込み中、解除 | フィルター | |
| 現在地、位置の利用、精度 | GPS、自分の場所 | |
| 行き先、ここへ向かう、案内 | 目的地、ナビ | 着く前は「案内をやめる」、着いたあとは「案内を終える」 |
| スタンプ、混雑(1〜5)、感想(面白い・美味しい・よさ) | 口コミ、評価、混み具合 | 押す、取り消す |
| 表示する印 | レイヤー | |

書き方:

- 文は「です・ます」で短く。「現在地が使えません」「検索・一覧・場所の情報は、このまま使えます。」
- ボタンは、押すと起きることを動詞で書く(「ここへ向かう」「取り消す」「解除」)。
- 数と単位の間は半角の空き(「150 m」「±8 m」「10 秒前」「4 件」)。地図の印の中だけ詰める(「6分」)。
- 名前や選んだものは「」で囲む(「『行きたい場所』で絞り込み中・2 件」)。括弧は全角。
- 絵文字は使わない。感嘆符も使わない。

## 色

テーマは 2 つ。`dark` が基本(夜と屋内)で、`light` は屋外の日なた向け。部品には意味の色(`bg-page` など)だけを使い、パレットの色(`violet-400` など)を直接使わない。

| 色 | 使う所 | 使わない所 |
|---|---|---|
| `action-primary`(ライラック) | 主な操作、選んだチップと階、チェック、フォーカスの輪 | 行き先 |
| `destination`(黄) | 行き先だけ(「ここへ向かう」、案内のカード、行き先の印と線) | ほかの意味。強調のための黄 |
| `event`(ミント) | 企画(建物の旗、屋外の企画の印、「正面の建物」、種別の行の文字) | |
| `parking`(青) | 駐車場の印と札 | |
| `facility`(白い丸) | 設備の印、地図の上の名前の札 | |
| `feeling`(ピンク) | 感想のスタンプ | |
| `congestion-1`〜`congestion-5`(オレンジの濃淡) | 混雑のスタンプ。必ず数字と一緒に | 混雑以外の段階 |
| `danger`・`danger-bg`・`danger-text`(赤) | 使えない・失敗の知らせ、削除 | 注意を引くための飾り |

- 文字は `text-primary`・`text-secondary` を `bg-page`・`bg-surface` の上に置く。色の付いた面の上の文字は、その色の `-on`(`action-on-primary`、`destination-on`、`event-on`、`danger-on` など)を使う。白を直接書かない。
- 行き先を文字で示すときは `destination-text`。ライトの黄は文字にすると読めない。
- ライトの `destination` は、背景と明るさが近い(1.4:1)。行き先の印・カード・帯には、必ず `destination-border` を付ける。
- 線は 2 種類。`border-subtle` は区切りとカードの縁、`border-control` は押せる部品と入力欄の枠(3:1 以上)。
- フォーカスは、2 px の `action-primary` の輪を 2 px 離して描く(どちらの面の上でも、ダーク 6.6:1 以上 / ライト 6.5:1 以上)。
- 押したときは `state-pressed` を面に重ね、押せないときは `opacity-disabled` で薄くし、理由を近くの文で出す。
- 文字と背景の組は、どのテーマでも 4.5:1 以上(印・アイコン・枠は 3:1)。数値は各トークンの説明にある。

## 文字

書体は Noto Sans JP の 1 つだけ。Google Fonts から読み込む。

```html
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+JP:wght@400;500;700;800&display=swap" rel="stylesheet">
```

- 大きさは 11・12・13・14・15・16・20・24・28 px の 9 段階だけ。文字のスタイル(`title`・`subtitle`・`body`・`caption` など)から選ぶ。
- 太さは 400(説明)・500(入力)・700(ラベル)・800(見出し・主な操作・数字)。
- 入力欄の文字は 16 px(`input`)。スマートフォンで勝手に拡大されない。
- 名前は 2 行まで、案内バーの名前は 1 行まで。入りきらないときは末尾を「…」にする。

## 余白・角・影・大きさ

- 余白は 4 px が基本(`space-1`〜`space-6`)。来場者の画面の左右は `space-4`(16 px)。カードは画面の端から 12 px。
- 押せる大きさは `touch-target`(44 px)以上。小さく見せるときも、押せる範囲は 44 px を取る。
- 角: ボタンとアイコンボタンは `radius-lg`、入力欄は `radius-md`、検索窓・帯・空の表示は `radius-xl`、カードとシートは `radius-2xl`、チップと地図の札は `radius-pill`。
- 影は `shadow-sheet` の 1 つだけ。地図の上に下から出る面(場所のカード、案内のカード、シート)に付ける。

## 画面の組み方

- 来場者: 下に `TabBar`(一覧・マップ・カメラ。起動時はマップ)。マップの上に `SearchField` と `Chip` の列、絞り込み中は `FilterBand`。場所を選ぶと下から `PlaceCard`、行き先にすると `DestinationCard`。
- 見る(場所のカード)と向かう(「ここへ向かう」)を分ける。地図の印を押しただけでは、行き先にしない。
- 運営: PC の画面。左に `DataTable`、右に `FormField` と `LocationPicker`。消す前に `DeleteConfirm` で、連動して起きること(検索から消える、案内が終わる)を先に見せる。

## 地図の印

- 印はすべて `map-ring` で縁取り、地図から浮かせる。地図の上に置くときは、親を `position: relative` にし、印に `x`・`y` を渡す。
- 縮小のときは丸だけ、拡大のとき(`zoomed`)は名前・種類・経過時間を出す。
- 近いスタンプはまとめる。代表は一番新しい混雑にし、ほかの件数を「+N」で出す(`StampMark` の `more`)。
- 行き先は、道なりの経路を描かない。現在地からの直線と、方角と距離だけ(`DestinationMark` の点線)。

## アイコン

- アイコンは `Icon`(29 個)。24 の格子に、丸い端の線で描く。色は文字の色を引き継ぐ。一覧は `NAsVI.Icon.names`。
- トイレは塗りつぶしの男女、案内所は丸で囲んだ「i」。
- アイコンだけのボタン(`IconButton`)には、必ず読み上げ用の `label` を付ける。
- ロゴはまだ無い。名前は文字で書く。

## 部品の使い方

部品は `window.NAsVI` にある React 18 の部品(`components/bundle.js`)。見た目は `components/bundle.css` と、トークンの CSS 変数で決まる。

```js
const { PlaceCard, FilterBand } = window.NAsVI;
React.createElement(FilterBand, { labels: ['行きたい場所'], count: 2, onClear: clear });
```

- 部品は 4 つの箱に分かれる: 基本の部品(Button、Chip など 12 個)、地図の印(7 個)、画面の部品(12 個)、運営の部品(PC。5 個)。
- 名前の付け方: 基本の部品は役割で(`Button`、`Banner`)、地図の印と画面の部品は概念の名前を頭に付ける(`PlaceRow`、`DestinationCard`、`StampMark`)。
- ※ の付いた部品(`BuildingFloorPlan`)は、概念設計の決定待ち(見取り図を新しい概念にするか。OQ-14)。
- 内部の名前(概念設計・API)は `Landmark`(API は `landmarks`)のまま。画面の言葉は「建物」、部品の名前は `Building*` にそろえる(D-020)。

## Design System で足したもの

部品の仕様(35 部品)とトークンの下書きに無く、ここで足したもの。

- トークン `border-control`: `border-subtle` は 3:1 に届かず、入力欄の枠に使えないため。
- トークン `danger-on`: 削除のボタンの文字。ライトの赤の上で 4.5:1 を取るため。
- トークン `destination-text`: 行き先を文字で示すため。ライトの黄は文字として読めないため。
- 部品 `Icon`: どの部品も同じ線のアイコンを使うため。
- いくつかの props(`components/index.d.ts` に【Design System で追加】と書いた)。

## まだ決まっていないこと

この部品で組んだ画面を確定にする前に、チームに確かめる。

- 「地図で指定する」(現在地が使えないとき。OQ-2)
- スタンプの期限の最終値(OQ-4。いまは混雑 30 分・感想はその日の閉場までで仮置き)と、近いスタンプをまとめる距離
- 文章で探す(拡張。OQ-8)、タグの名前の決まりと上限(OQ-13)
- 建物の輪郭を、端末へ同梱するか API から返すか(OQ-16)
- 実機の屋外での見え方(トイレのアイコン、ライトの行き先の黄)
