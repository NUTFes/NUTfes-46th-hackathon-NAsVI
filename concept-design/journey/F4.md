# F4 種類・自分用タグから選ぶ(optional)

> 2026-11-22: main(995931a 以降。決定 D-007・D-012・D-014、画面の遷移 screens.yaml の F4・F4-tag)に合わせて、始点・前提・終点・基本シナリオ・失敗時を書いた。同期(concepts.yaml)と criteria.yaml から導いた。★要確認は、チームの確認が取れるまで確定として扱わない。F4 を P1 に入れるか自体が未決(OQ-3)。

## 1. 目的

- 価値: 行き先が決まっていない来場者が、種類(飲食、展示など)や自分用のタグ(行きたい場所、お気に入り、自作)から場所を選べる。タグで絞ると、見える場所も絞られる
- 目的(評価基準側): 行き先が決まっていない来場者が、種類から選べる  [proposed]
- 登場する人: 来場者、運営(種類を定めて付ける)

## 2. 使う概念と原理(基本シナリオの骨格)

- **Place**: 運営が場所の名前・種別・位置・説明を登録しておくと、来場者はその場所の一覧と個々の情報を見られる。
- **Labeling**: 運営が種類「飲食」を定めて項目に付ける。来場者が種類「飲食」で絞ると、その種類が付いた項目だけが見える。来場者は自分用のタグ(行きたい場所、お気に入り、自作)を項目に付けられ、そのタグで絞ると、自分が付けた項目だけが見える。他の来場者のタグは見えない。タグを外すか、絞り込みを解除すると、元の見え方に戻る。

自分用のタグは、各自の端末の中にだけ保存し、API には載せない(decisions D-014)。絞り込みは、一覧・地図・検索結果のすべてに効く(decisions D-012)。

## 3. ジャーニー

| 項目 | 内容 |

### 基本シナリオ(同期から導いた手順)

種類・タグで選ぶ(F4):

1. 来場者が一覧(またはマップ)の上のチップで、種類(飲食・展示・体験・ステージ)か自分用のタグを押す(`Request.applyFilter` → `Labeling.applyFilter`)。 → 絞り込みステータスが、その来場者の `filtering` に入る。
2. 利用者に見えること: 一覧、地図の印、検索結果が、付いた場所だけに絞られる。「『X』で絞り込み中・N 件」の帯と「解除」が出る。1 操作で済む(評価基準)。
3. 来場者が一覧から場所を選び、場所のカードを開く。
4. 絞り込みを解除する(`Request.clearFilter` → `Labeling.clearFilter`)と、すべての場所が見える。

タグを付ける・作る(F4-tag):

1. 来場者が場所のカードで、「行きたい場所」か「お気に入り」を押す(`Request.markPlace` → `Labeling.attach`)。押し直すと外れる(`Request.unmarkPlace` → `Labeling.detach`)。
2. 自作のタグは、「＋ タグ」から開くシートで名前を入れて作る(`Request.defineMyTag` → `Labeling.defineFor`)。作ると、その場所に付く。
3. 利用者に見えること: タグが付いたことと、そのタグでチップが増えること。タグは端末内にだけ保存されると、シートに書く。

運営が種類を定めて付ける(運営の画面 O1):

1. 運営が種類を定める(`Request.defineLabel` → `Labeling.define`)。
2. 運営が場所に種類を付ける(`Request.assignLabel` → `Labeling.attach`)。条件: 場所が `Place.places` に含まれ、実行者が場所を管理できる(OQ-1)。

連動(利用者の操作に続いてシステムが行うこと):
- `Place.remove` のあと `Labeling.release`(取り除かれた場所に付いたタグ・種類がすべて外れる)。

### 失敗・中断したとき

- **その種類・タグに場所が無いとき:** 空であることと、絞り込みを解除する手を見せる(評価基準)。検索で一致しないときも、「絞り込みを解除して探す」を出す(D-012)。
- **存在しないタグで絞ろうとしたとき:** `Labeling.applyFilter` の事前条件(label が labels に含まれる)を満たさない。通常の操作では起きない。端末のデータが壊れたときの扱いは ★要確認。
- **他の来場者のタグ:** 見えない。端末内に保存するので、そもそも届かない。
- **端末のデータが消えたとき:** 自分用のタグは戻らない。来場者への伝え方(シートの文言と置き場所)は、画面設計で仮置き ★要確認(イシュー #17)。
- **自作タグの名前:** 空欄・重複・文字数・上限は未決(OQ-13)。
- **絞り込み中に、タグを外して該当が無くなったとき:** その場所が一覧から消える。カードを開いている場合の扱いは ★要確認。
- **通信が切れたとき:** 自分用のタグと絞り込みは、端末内で完結する(通信が要らない)。運営の種類は、場所のデータと同じ取得に依存する。
- **権限が無いとき:** 運営の種類の登録は、場所を管理できる実行者だけ(OQ-1)。

## 4. 評価基準

成功条件:
- 種類を選んでから、その種類の場所の一覧が出るまで、1 操作で済む
- お気に入りなどのタグで絞ると、見える場所が絞られ、いま絞り込み中であることが分かる

失敗時の扱い:
- その種類に場所が無いとき、空であることが分かる

デモの場面: 「飲食」を選ぶと、飲食の場所だけが出るところ

作らないこと: 複数の種類の掛け合わせ(種類 1 つと、タグ 1 つを重ねて絞れるか、ワイヤーフレームでは読み取れていない。マップのモックは重ねられる形にした ★要確認)
