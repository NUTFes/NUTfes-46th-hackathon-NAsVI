# F2 行き先へ向かう

> 2026-11-22: main(995931a 以降。決定 D-013、画面の遷移 screens.yaml の F2・F2-noloc)に合わせて、始点・前提・終点・基本シナリオ・失敗時を書いた。同期(concepts.yaml)と criteria.yaml から導いた。★要確認は、チームの確認が取れるまで確定として扱わない。

## 1. 目的

- 価値: 来場者が、自分の現在地と行き先の位置関係をつかんで、迷わず向かえる
- 目的(評価基準側): 来場者が、いまの場所から行き先に、迷わず向かえる  [proposed]
- 登場する人: 来場者

## 2. 使う概念と原理(基本シナリオの骨格)

- **Place**: 運営が場所の名前・種別・位置・説明を登録しておくと、来場者はその場所の一覧と個々の情報を見られる。
- **Position**: 来場者が位置の利用を許可すると、端末の報告に合わせて、自分の現在地だけが見える。現在地には報告の時刻と精度が付く。
- **Destination**: 来場者が項目を 1 つ選ぶと、それが行き先として保たれる。現在地が変わるたびに、行き先への方角と距離が更新される。選び直すか解除するまで行き先は変わらず、解除すると道案内も無くなる。

行き先の道案内は、道なりの経路でなく、方角と距離だけ(decisions D-003)。

## 3. ジャーニー

| 項目 | 内容 |
|---|---|
| 始点(何をきっかけに使い始めるか) | 来場者が場所を見つける(F1 と同じ。screens.yaml の F2 の始まり)。場所のカードを開いた状態 |
| 前提(どこで、どの端末で、何を持っているか) | 会場の中か外で、位置の利用を許可した来場者の端末。許可していないときは F2-noloc(下の失敗時)から始める |
| 想定の場面(入力の scenario) | 来場者が行き先を 1 つ決めると、自分の現在地から行き先までの方向と距離が分かる |
| 終点(何が起きたら終わりか) | 行き先に着くと「着きました」と出て、案内を終える(画面 V1-n。到着とみなす距離は、ワイヤーフレームの仮置き 20 m。設計の根拠は無い ★要確認) |

### 基本シナリオ(同期から導いた手順)

1. 来場者が位置の利用を許可する(`Request.allowLocation` → `Position.allow`)。端末が現在地を報告する(`Request.reportPosition` → `Position.update`)。 → 現在地、時刻、精度が地図に出る。
2. 来場者が場所のカードを開く(F1)。カードを開いただけでは、行き先にしない。
3. 来場者が「ここへ向かう」を押す(`Request.chooseDestination`)。条件: 場所が `Place.places` に含まれる。 → システムが `Destination.choose` を実行し、続けて同期 `guide-on-choose` が方角・距離・更新時刻を `Destination.updateGuide` で保つ。
4. 利用者に見えること: カードが案内の表示に変わり、行き先の名前、方角、距離、何秒前の更新か(`Request.showRoute`)が出る。追加の操作は要らない(評価基準)。
5. 来場者が歩く。端末が現在地を報告するたびに、同期 `guide-on-move` が方角と距離を更新する。
6. 来場者が「案内をやめる」を押す、または行き先に着く。 → システムが `Destination.clear` を実行し、道案内が無くなる。

連動(利用者の操作に続いてシステムが行うこと):
- `Place.remove` のあと `Destination.clear`(条件: 行き先が、取り除かれた場所である)。運営が場所を消すと、その場所を行き先にしている来場者の案内は終わる。

### 失敗・中断したとき

- **位置の利用を拒否している(F2-noloc):** 地図の上に「現在地が使えません」の帯を出し、方角・距離とスタンプが使えないことと、検索・一覧・場所の情報は使えることを示す。次の手は「位置の利用を許可」。「地図で指定する」を入れるかは OQ-2(画面では仮置き)。拒否の後の許可は `Position.allow` の事前条件(拒否に含まれない)に当たるため、拒否を取り消す操作の有無は ★要確認。
- **現在地が古い・精度が低い:** 更新の経過時間と精度(例: 10 秒前・±8 m)を、案内に添える(評価基準「現在地が取れているか、古いかが分かる」)。古いとみなす時間と、案内を止める精度の基準は未決 ★要確認。
- **行き先の場所が消えた:** `Place.remove` の連動で案内が終わる。来場者に何を見せるか(終わったことを伝えるか)は ★要確認。
- **行き先を選び直した:** `Destination.choose` は、既にある行き先を置き換える。新しい行き先の案内が出るまで、前の案内を見せない。
- **通信が切れたとき・応答が遅いとき:** 現在地と行き先は端末内で足りるかは、来場者の識別と保存先の決定(OQ-12)に依存する ★要確認。
- **権限が無いとき:** 来場者の操作に権限の区別は無い。

## 4. 評価基準

成功条件:
- 行き先を決めてから、現在地との位置関係が分かるまで、追加の操作が要らない
- 現在地が取れているか、古いかが利用者に分かる

失敗時の扱い:
- 位置の利用を拒否された、または取れないとき、何ができなくなり、代わりに何ができるかが分かる(OQ-2)

デモの場面: 会場の外か中で、行き先を選び、現在地から行き先への方向と距離が出るところ

作らないこと: 道なりの経路案内, 屋内の位置検知
