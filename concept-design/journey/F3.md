# F3 混雑・感想を知る

> 2026-11-22: main(995931a 以降)に合わせて、始点・終点を screens.yaml の F3 に揃えた。
> 2026-11-19: 旧 Congestion(場所ごとの混雑)の版から、Stamp(足元のスタンプ)の版へ書き直した。基本シナリオ・失敗時の項は、同期(concepts.yaml の press-stamp / retract-stamp / show-stamps)と criteria.yaml の F3 から導いた。★要確認は、チームの確認が取れるまで確定として扱わない。

## 1. 目的

- 価値: 来場者が、足元に押されたスタンプ(混雑 1〜5、面白い、美味しい、よさ など)から、混んでいる場所や良い場所を知って、行く先や時間を選べる
- 目的(評価基準側): 来場者が、混んでいる場所や良い場所を、他の来場者のスタンプで知って、行く先や時間を選べる  [proposed]
- 登場する人: 来場者(押す人と見る人は、どちらも来場者)

## 2. 使う概念と原理(基本シナリオの骨格)

- **Position**: 来場者が位置の利用を許可すると、端末の報告に合わせて、自分の現在地だけが見える。現在地には報告の時刻と精度が付く。
- **Stamp**: 来場者が自分のいる地点にスタンプ(混雑 1〜5、面白い、美味しい、よさ など)を押すと、そのスタンプが地点と時刻つきで残る。他の来場者が見ると、その地点にスタンプが見える。押した本人が取り消すと、スタンプは見えなくなる。

スタンプは場所(Place)ではなく、押した人の現在地(Point)に付く。そのため、場所の登録・削除とは連動しない(decisions D-009)。

## 3. ジャーニー

| 項目 | 内容 |
|---|---|
| 始点(何をきっかけに使い始めるか) | 来場者がマップを開く(画面の遷移は screens.yaml の F3)。押す側は、他の人に伝えたいことがその場にあるとき ★要確認 |
| 前提(どこで、どの端末で、何を持っているか) | 会場の中で、位置の利用を許可した来場者の端末。見る側は、位置を許可していなくても見られるか ★要確認(OQ-2) |
| 想定の場面(入力の scenario) | 来場者が自分のいる地点にスタンプを押すと、他の来場者は、その地点のスタンプと押された時刻を見られる |
| 終点(何が起きたら終わりか) | 足元にスタンプが押され、取り消しもできると分かる(screens.yaml の F3 の終わり)。見る側は、行き先や時間を決めた |

### 基本シナリオ(同期から導いた手順)

押す:

1. 来場者が位置の利用を許可し、端末が現在地を報告する(`Position.allow`、`Position.update`。F2 と共通)。
2. 来場者がスタンプの種類を選んで押す(`Request.pressStamp`)。条件: 押す人の現在地(`Position.at`)が地点として使える。 → システムが `Stamp.press` を実行し、その地点・種類・時刻のスタンプを残す。
3. 利用者に見えること: 押したスタンプが、自分の足元の地点に出る。

見る:

1. 来場者が地図でスタンプを見る(`Request.showStamps`)。 → システムが、スタンプの種類・地点・押された時刻を返す(`Request.respond`)。
2. 混雑スタンプは、許容時間(OQ-4)を超えたものを答えに出さない。感想のスタンプ(面白い、美味しい、よさ)に期限を付けるかは OQ-4。
3. 利用者に見えること: 地点ごとのスタンプの種類と、押されてからの経過。

取り消す:

1. 押した本人が取り消す(`Request.retractStamp`)。条件: スタンプの押し手が本人である。 → システムが `Stamp.retract` を実行し、そのスタンプは見えなくなる。

連動(利用者の操作に続いてシステムが行うこと): なし(Place の削除とは連動しない)。

### 失敗・中断したとき

- 現在地が取れない・位置を許可していないとき: スタンプを押せないことと、次の手(位置の許可、手での指定)を見せる。手での指定を入れるかは OQ-2。
- 現在地の精度が低いとき: 押せるか、押す前に確認を見せるか ★要確認(精度の基準は未決)。
- 古い混雑スタンプ: 新しい情報として見せない。許容時間は OQ-4。
- 他人のスタンプを取り消そうとしたとき: 取り消せない(`Stamp.retract` の事前条件)。画面では、自分のスタンプにだけ取り消しを出す。
- 通信が切れたとき・応答が遅いとき: 押したスタンプが共有されたか分かるようにする。保存先(端末内か共有の保存先か)は未決のため、ここでは決めない ★要確認。
- 同じ地点に同じ種類を連続で押したとき: 重ねて数えるか、まとめるか ★要確認(未決。OQ-4 の周辺)。

## 4. 評価基準

成功条件:
- 来場者が、地点ごとのスタンプの種類と、それがいつ押されたかを一目で見分けられる
- スタンプを押すまでの操作が少ない(目安: 2 操作以内。現在地が取れている場合)

失敗時の扱い:
- 現在地が取れないとき、スタンプを押せないことと、次の手(位置の許可、手での指定)が分かる(OQ-2)
- 古い混雑スタンプを、新しい情報として見せない(OQ-4)

デモの場面: 来場者が足元にスタンプを押すと、別の来場者の見える表示に、その地点のスタンプが出るところ

作らないこと: 混雑の自動計測, 混雑の予測
