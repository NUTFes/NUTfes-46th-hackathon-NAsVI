# 決定ログ(1 件の書式)

`design-system/decisions.md` に、判断ごとに次を 1 件として足す。「未確認」のまま進める決定は、そう明記して残す(後で見直す手がかりになる)。

```markdown
## 決定: (一行で)
- 日付:
- 段階: (原則 / 分類 / トークン / コンポーネント / 適用)
- 決めた内容:
- AI が出した案と根拠:
- 検討した代替案と、却下した理由:
- 前提(崩れたら見直す条件):
- 人間の確認: 誰が、何を使って、何を確かめたか
- 確認の結果: (確認済 / 一部のみ確認 / 未確認)
- やり直しコスト: (低 / 中 / 高)
```

## 記入の決まり
- 「AI が出した案」と「人間が確かめた事実」を混ぜない。人間の確認の欄が空なら、確認の結果は「未確認」。
- やり直しコストが「高」(命名・分類の方針、API 契約と絡むもの)は、確認済でなければ次のステップに進まない。
- 決めたのはチーム。AI は決めない。
