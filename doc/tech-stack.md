# 技術スタックとデプロイの決定記録(暫定)

作成: 2026-11-23 / 状態: **暫定**(チーム確認前)
前提にした概念設計: `concept-design/` の `567b90b`(#33、D-033 まで反映)。API 設計は `concept-design/api/review-ledger.yaml`(API-24・25 を含む)

各決定に、理由と「見直す条件」を付ける。見直す条件が起きたら、決定を差し替える。

## 前提(チームから聞いたこと)
- 言語は TypeScript であればよい。ほかの制約はない。
- フロントは Vue を使ってみたい(開発者の希望)。
- Cloudflare で一括して構築し、管理者ページは Cloudflare Access(ゼロトラスト)で守りたい。
- 来場者は不特定多数。認証が要るのは運営側。

## 決定

| # | 領域 | 決定 | 理由 | 見直す条件 |
|---|---|---|---|---|
| T1 | フロント | **Vue 3 + Vite + TypeScript の SPA**(Nuxt は使わない) | 画面は地図と AR が中心で、SSR が要らない。Vue を使いたいという希望とも合う。 | SSR や SEO が要る画面が出たとき |
| T2 | 配信・デプロイ | **Cloudflare Pages**(フロント)+ **Workers**(API)+ **D1**(DB)。`main` への push で本番、PR ごとにプレビュー URL | HTTPS が標準で付く(GPS・カメラ・方位センサーの条件)。サーバー運用が要らない。 | 無料枠を超える見込みが出たとき |
| T3 | API | **Hono**。**`openapi.yaml` を正**とし、型は仕様から生成する(`zod-openapi` で実装から仕様を作る運用はしない) | `api-design` スキルは、仕様 → 台帳 → 機械検査の順で、仕様を正としている。 | 仕様と実装のずれが頻発したとき |
| T4 | 管理系の保護 | **Cloudflare Access** で `/admin/*` と `/api/admin/*` を守る。Workers は `Cf-Access-Jwt-Assertion` を検証して、実行者のメールを取る。**当面は実行委員(管理者)のみ**(OQ-1、D-033。API-12 で確定済み)。Access を通った人を「場所を管理できる実行者」とみなし、ロール表・所有表は持たない | 画面設計に、企画・出店向けの画面がない。Access だけで足りる。 | 出展者が自分の企画を編集する画面を作るとき(`Place` の持ち主、ロール表、所有表を足す) |
| T5 | 来場者の扱い | **アカウントを持たせない。Better Auth は入れない**。現在地・行き先・自分用タグは端末内。スタンプの取り消しは、押したときに返す証(proof)の一致で確かめる(D-021)。荒らし対策はレート制限 | 概念設計が、来場者を識別しない方向(D-014、D-021)と合う。 | 来場者のアカウントが要る機能が出たとき |
| T6 | AR | **通常版(現在地・向き・建物の輪郭)を本線**にする(D-018)。位置と方位の計算は、フレームワーク非依存の TypeScript モジュールに切り出す。ラベルの毎フレーム更新は Vue のリアクティブの外(`requestAnimationFrame` で直接更新)で行う。MindAR は拡張として残す | PR #4 の通常版が、この方式で動いている。基準画像を撮り溜める必要がなく、会場全域で動く。 | 実機で方位の誤差が大きく、ラベルが使い物にならないとき |
| T7 | スタンプなどの反映 | **Server-Sent Events(`/changes`)**。API 設計の台帳 API-24(確定、2026-11-22)に従う。出来事の形は API-25(仮置き)。当初案の 15〜30 秒のポーリングは取り下げた | 確定済みの API 設計に合わせる。 | 電波の弱さなどで SSE が使えないとき(API-24 も見直す可能性に触れている)。配信の仕組みは下の「まだ決めないこと」 |
| T8 | リポジトリ | モノレポ(`web/`、`api/`)。pnpm のワークスペース。Node は mise で固定する | 既存の運用(mise)を保つ。 | — |

| スタンプの期限 | 仮置き(混雑 30 分、感想は閉場まで。D-022、OQ-4)。 |
