# 端末内の処理の一覧(下書き)

作成: 2026-11-24 / 状態: **下書き**(人間の確認前。集めただけで、新しい決定は含まない)
前提にした `main`: `dceb8e7`(#34)。出どころは、API 設計の台帳(`concept-design/api/review-ledger.yaml`)、`concepts.yaml`、`openapi.yaml`、`design-system/props-api-check.md`、`doc/tech-stack.md`。

## 目的
API 設計の機械検査(`openapi_check.py`)は、サーバーの契約だけを見る。**端末で行う処理は、どの検査にも引っかからない。** 端末の処理は、サーバーが返す項目に依存するので、ここで「処理 × 入力になる API の項目」を 1 か所に集め、足りない項目が実装の途中で見つかるのを防ぐ。

## 1. 端末で完結する操作(API に載らない)
`openapi.yaml` の `x-excluded-requests` と、台帳の根拠。

| 操作 | 根拠 | 保存するもの | 状態 |
|---|---|---|---|
| 位置の許可・拒否・報告(`allowLocation`・`refuseLocation`・`reportPosition`) | API-5 | 現在地(継続的にはサーバーに送らない。スタンプを押すときの地点 `at` だけ送る) | 確定 |
| 位置の手入力(`setPosition`) | API-5 | 現在地 | **P1 に入れるか未決(OQ-2、#10)** |
| 行き先の設定・解除(`chooseDestination`・`clearDestination`) | API-5、D-013、D-026 | 行き先の場所 id | 確定。着く前の「案内をやめる」と着いた後の「案内を終える」は同じ操作 |
| 経路(`showRoute`) | API-5、D-003 | なし(直線の方角と距離を、その場で計算) | 確定(経路は直線のまま) |
| 自分用タグの作成・付け外し(`defineMyTag`・`markPlace`・`unmarkPlace`) | D-014 | タグと、タグを付けた場所の id | 確定。固定の「行きたい場所」「お気に入り」+自作 |
| 絞り込みの設定・解除(`applyFilter`・`clearFilter`)、一覧の閲覧(`browse`) | API-8、D-014 | 絞り込みの状態 | 確定 |

## 2. 端末で行う計算(入力になる API の項目つき)

| 処理 | 入力(API の項目 / 端末のデータ) | 規則 | 根拠 |
|---|---|---|---|
| 絞り込み(検索結果にも効かせる) | 場所の `labelIds`(運営の種類)、端末のタグ | 運営の種類どうしは OR、自分用のタグは AND。設備は絞り込まない | API-8、D-012、D-016 |
| 距離・方角の計算 | 場所の位置、端末の現在地 | 直線(D-003) | props-api-check 行 6・距離 |
| 建物ごとの企画数 | 場所の `landmarkId` | 絞り込み中は絞った後の数。設備は数えない | D-017、D-030 |
| 建物の正面判定(カメラ) | 現在地、向き、建物の `footprint` | 現在地と向きは端末の中で計算し、サーバーに送らない | D-018 |
| 各企画の方向・距離・「建物の奥か」 | 現在地、向き、輪郭 | 概念の外の計算 | D-025 |
| 見取り図の上の位置の換算 | 現在地、見取り図の `bounds`(north・south・east・west) | 換算は端末が行い、API は `bounds` を保存して返すだけ | API-30 |
| 期限切れスタンプの非表示 | スタンプの `expiresAt` | `expiresAt` を過ぎたら消す。端末の時計が少しずれても許容 | API-38 |
| 混雑の濃淡 | 有効なスタンプ(種類・位置・`pressedAt`・`expiresAt`) | 場所ごとに集計して濃淡にする | `doc/tech-stack.md` の「端末に任せる方針」 |
| スタンプの取り消し | 押したときの応答の `proof`(端末が保存) | 取り消すとき `X-Stamp-Proof` ヘッダーで渡す。端末のデータが消えると取り消せない(受け入れ済み) | API-13、D-021 |
| 場所の id の整合 | 一覧にない id、`placeRemoved` で受け取った id | 該当するタグ・行き先は表示しない。**消すか残すかは端末が決めてよい** | API-31 |
| 一覧の取り直し | `/changes` の `id`・`Last-Event-ID`・`resync` | 保存した cursor から `since` でつなぐ。全件取得は初回と `resync` のとき | API-42、`tech-stack.md` |

## 3. 端末に保存するデータ

| データ | 内容 | 消えたとき |
|---|---|---|
| 自分用タグと付けた場所の id | D-014 | 戻らない(同期なし)。来場者への案内文は #17 で未決 |
| 行き先、絞り込みの状態 | API-5、API-8 | 戻らない(困らない) |
| スタンプの `proof` | 押したスタンプごと | **取り消せなくなる**(受け入れ済み。スタンプは時間で消える) |
| 一覧・建物の輪郭・見取り図のキャッシュ | 版つき | 取り直す |
| cursor | `/changes` の続き | 全件を取り直す |

## 4. 集めている途中で見つかった、未決・確認の点
実装で迷いやすいものだけ。すべて、人間の判断が要る。

1. **削除された場所のタグ・行き先を、端末が消すか残すか。** API-31 は「端末が決めてよい」とだけ書いている。画面の仕様(消えたことを知らせるか)が、デザインシステムにあるかは未確認。
2. **`Labeling` で `undefine` した Label が、絞り込みに残るときの扱い。** `concepts.yaml`(106 行)に「未確認」と書かれている。運営の種類を消す操作は管理者のみだが、端末の絞り込みが古い種類の id を持ったままになりうる。
3. **位置の手入力(OQ-2)。** 決まらないと、位置が取れないときの画面と、端末の処理の範囲が決まらない。
4. **端末のデータが消えることの来場者への案内。** 文言と置き場所が未決(#17)。
5. **保存先の技術**(localStorage か IndexedDB。#17)。キャッシュの量(建物の輪郭と見取り図)によっては、localStorage では足りない可能性がある(推論。数値は未確認)。
6. **端末の時計のずれ。** 期限の判定(API-38)は、端末の時計に依存する。許容と決めてあるが、「どの程度のずれまで許容か」の数値はない。
7. **P1 の端末の対応範囲。** iOS Safari と Android Chrome での位置・方位・カメラの許可は、実機で未確認(`tech-stack.md` の E1〜E5)。端末の処理の前提が、まだ確かめられていない。

## 5. API 側に戻す候補
今回の集計では、**「API に足りない項目」と断定できるものは、見つからなかった。** 次の 2 点は、実装で足りなくなる可能性があるので、実装前に確認する。
- 4-1(削除された場所の知らせ方)は、`placeRemoved` で足りるか。
- 4-5(キャッシュの量)は、`GET /landmarks` の応答の大きさ(輪郭の点の数)に依存する。API-33 の応答の大きさを、実測で確かめる。
